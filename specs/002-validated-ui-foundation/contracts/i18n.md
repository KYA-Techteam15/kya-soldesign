# Contract: French and English localization

## Locale policy

- Supported locales: `fr`, `en`.
- Default: `fr`.
- UI-BASE-001 is incomplete until both catalogs are complete.
- Locale affects labels, number/date formatting, and accessible names; it does not change canonical values, ids, units, hashes, or provenance.

## Typed catalog

```ts
export const fr = {
  'app.name': 'KYA SolDesign',
  // ...all UI-BASE keys
} as const;

export type MessageKey = keyof typeof fr;
export const en: Record<MessageKey, string> = {
  'app.name': 'KYA SolDesign',
  // ...same keys, no fallback
};
```

## Required checks

1. Key-set equality between `fr` and `en`.
2. No empty or whitespace-only message.
3. No raw key returned from the translation function in production.
4. No hard-coded user-visible copy in UI-BASE React components except product name, standards identifiers, and unit symbols explicitly allowlisted.
5. Route-level Playwright assertions in both locales.
6. Visual/text-expansion checks with English copy at 1024 × 768.

## Formatting

- Use `Intl.NumberFormat` and `Intl.DateTimeFormat` at presentation boundaries.
- Engineering unit symbols remain standardized and are not translated.
- Do not parse localized strings into canonical data.
- Currency formatting requires integer minor-unit inputs and an ISO currency code; financial calculations remain unavailable in this feature.

## Language switching

- Switching locale preserves current route and in-memory draft.
- Dialog/palette content updates without losing focus.
- `<html lang>` updates to the selected locale.
- The locale toggle exposes its current value and next action accessibly.
