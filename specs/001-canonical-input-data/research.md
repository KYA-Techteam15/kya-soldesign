## Source and mapping decisions

| ID | Source field or behavior | Classification | Canonical treatment |
|---|---|---|---|
| SRC-DATA-001 | Reference module `power`, `vmp`, `voc_stc`, `imp_stc`, `isc_stc` | adopt | Map to explicit `nominalPowerW`, `voltageAtMaximumPowerV`, `openCircuitVoltageV`, `currentAtMaximumPowerA`, `shortCircuitCurrentA`. |
| SRC-DATA-002 | Reference battery `capacity`, `voltage`, `max_dod`, `round_trip_efficiency`, `cycle_life` | adopt | Map capacity as Ah and derive Wh only in a documented pure function. Map percentages to ratios. Preserve missing cycle life as `null`. |
| SRC-DATA-003 | Reference inverter electrical fields | adopt | Map all unit-bearing fields explicitly. A surge value equal to nominal is retained with a warning, never interpreted as a verified overload capability. |
| SRC-DATA-004 | Legacy root catalog price, owner, and datasheet fields | compare-only | They are not engineering facts for this feature and do not enter canonical snapshots. |
| SRC-DATA-005 | Legacy profile `shape` | transform | The legacy view model divides each shape value by its sum before deriving hourly energy. The two stored shapes each sum to 1.06, so canonical fractions are deterministically `rawWeight / 1.06`; raw values and source hash remain traceable. |
| SRC-DATA-006 | Locality and weather-source reference files | adopt | Preserve coordinates and references. Elevation, IANA timezone, interval and weather measurements are absent, so no weather series is emitted. |
| SRC-DATA-007 | Legacy Python database shape and services | reject | Duplicated state/service behavior and database internals are not migration targets. |

## Field requirement matrix

| Entity | Mandatory to import | Explicitly nullable | Deferred use |
|---|---|---|---|
| PV module | source identity, manufacturer, model, nominal power W, Vmp V, Voc V, Imp A, Isc A | area m², temperature coefficients, NOCT | temperature correction and physical layout |
| Battery | source identity, manufacturer, model, nominal voltage V, capacity Ah | usable depth-of-discharge, round-trip efficiency, cycle life, technology | storage reliability, lifecycle, compatibility |
| Inverter | source identity, manufacturer, model, nominal AC power W, nominal DC voltage V | surge power W, AC voltage V, efficiency ratio, PV/MPPT/charging limits, parallel capability | compatibility, protection, dispatch |
| Locality | source identity, name, country code, latitude, longitude | elevation m, IANA timezone | solar/weather association |
| Weather metadata | source identity, locality identity, provider, source name | default tilt/azimuth | a future weather import attaches interval, timestamps and measurement units |
| Load profile | profile identity, display name, 24 finite non-negative weights with positive sum | none after normalization | energy simulation |

## Reproduced data findings

- Battery cycle life is present in 1 of 366 reference records; 365 values stay unknown.
- No inverter record declares a parallel capacity greater than 1.
- 38 of 84 inverter records have overload power equal to nominal power; these remain usable but do not prove surge performance.
- The two legacy hourly profiles each contain 24 non-negative values and sum to 1.06. The former implementation normalizes the sum before assigning daily energy.
- No source weather series, timestamp convention, interval, elevation, or timezone exists in the audited source set.

## NFR-DATA-001 benchmark

`tools/migration/benchmark-reference-import.mjs` clones the audited module records to exactly 1,000 in-memory records, performs one unmeasured warm-up import, then measures one deterministic import with `process.hrtime.bigint`. The script requires explicit `--modules` and `--out` paths and writes its evidence to `benchmark.json`.

On 2026-08-11, the measured import took **175.2454 ms**, accepted 998 records and quarantined the two repeated records whose source electrical facts violate the canonical PV constraint. This is below the 2,000 ms NFR threshold. The result is recorded in `benchmark.json`; its elapsed time is evidence only and is intentionally not a canonical data artifact.
